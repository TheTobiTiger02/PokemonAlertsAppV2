# Per-surface alert filters + map performance overhaul

The app currently has four separate, inconsistent filter implementations (feed, map, widget, notifications), and the map re-renders everything far too often for the new Darmstadt alert volume. Plan: one shared category model with an independent selection per surface, a "Filters" hub in Settings, and a targeted map performance rework.

## 1. Shared category foundation
- Reuse the existing `AlertCategory` enum (`ui/alerts/AlertVisualStyle.kt`: SPAWN, RAID, QUEST, ROCKET, KECLEON, HUNDO, NUNDO, PVP, RARE, WEATHER — already has accent colors) as the canonical filter vocabulary.
- New `data/AlertCategoryFilter.kt`: one classifier `PokemonAlert.categories(): Set<AlertCategory>` replacing the three duplicated type-matching implementations (feed `hasCachedType` chains, map `categoryForMapAlert`, widget fuzzy `matchesWidgetTypes`), plus selection-matching helpers.
- `AlertPreferences`: new keys `feedCategories`, `mapCategories`, `mapShowDismissed` (empty set = show all = default, per your "everything on" choice). One-time migration: old `selectedAlertFilterName` tab → category set (RARES → {RARE, SPAWN}, etc.); widget tokens → categories.
- `AlertFilter` enum stays only as a migration/compat shim; `FilterPreset` gains a `categories: Set<String>` field with backward-compatible decode (old presets keep working).

## 2. Feed
- Replace the single-select tab filter with **multi-select category chips** (accent-colored when active, live count per category, "All" chip clears). Filter bottom sheet becomes a category grid with switches + counts; presets save/restore categories. Search, sort, area, distance, walk-time, dismissed all unchanged.

## 3. Map
- Map gets its **own** filter: `selectedMapCategories` + `mapShowDismissed`, edited via a new filter button → bottom sheet (category chips with counts + show-dismissed switch + "independent of feed" hint). `visibleMapAlerts` switches to category-set matching.

## 4. Widgets
- Keep per-instance config; migrate `selectedAlertTypes` tokens to categories; add per-widget **area override** (Inherit app / Fixed, mirroring the existing distance modes). Redesigned `WidgetConfigActivity`: category grid with switches + live counts. Both widgets (Alerts + NearbyRadar) go through the aligned `WidgetAlertFilter`.

## 5. Notifications
- Burst cap in `AlertNotifier`: per wave, post at most ~25 individual notifications (most urgent first); the rest collapse into the existing group summaries with a "+N more" line.
- Found-fix: `RAID_TIER_REGEX` (`\d+|mega`) never matches Elite/Primal — fix exclusion matching.

## 6. Settings → "Filters" hub
- Rework the existing ALERT_FILTERS destination into a hub with segmented tabs **Feed | Map | Widgets | Notifications**: each tab shows a shared `CategoryFilterGrid` (switch rows, accent dot, live count badges) plus that surface's extras (feed: area/distance/walk/presets; map: dismissed, countdown labels, spawn radius; widgets: list of placed widgets with summaries + jump into per-widget config; notifications: existing toggles, advanced filters, quiet hours — reusing `TypeFilterSection`/`SpeciesFilterButton`). Follows the app's Material 3 language, counts streamed from the repository alerts flow.

## 7. Map performance
- **Clustering on camera settle, not every zoom tick**: quantized zoom/center, recompute only when the gesture ends or a bucket is crossed.
- **Grid-bucket clustering** (spatial hash + 3×3 neighbor merge) replacing the O(n²) all-pairs union-find, preserving spawn-circle guard and expanded/protected semantics.
- **Viewport culling**: filter alerts to visible bounds + margin before clustering (both backends).
- **Hard marker cap** (~350): if still above cap, progressively widen the cluster cell.
- **Adaptive countdowns** (your choice): ≤ ~80 markers → 1 s second-precision labels; crowded → minute-precision labels ("12m") refreshed per minute. Feed cards always stay second-precise.
- **MapLibre**: remove its duplicate internal clustering; replace `removeAnnotations()` + full re-add (currently twice per tick) with id-based annotation diffing (add/remove/update only changed); HashMap click lookup; single render pass.
- **Caches**: marker icon + artwork LruCaches sized by bytes (~32/16 MB) instead of entry counts; cluster bitmaps cached by (category, count, size) so membership changes don't force redraws.
- **Spawn circles**: render only when zoomed in (≥ ~14) and capped at the nearest ~60.

Check jank with `dumpsys gfxinfo`, fix whatever turns up, re-verify.
