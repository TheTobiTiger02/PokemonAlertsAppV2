## Phase 1 — Verify & fix static bug candidates (each: read → confirm → fix → unit test where feasible)
1. **Race that can delete fresh FCM alerts**: `clearExpiredAlerts` does read-then-`replaceAll` (clearAll+insert) while `fetchMutex` only guards `fetchAlerts` — an FCM alert inserted in between gets wiped (PokemonAlertsRepository.kt:169-178).
2. **Lost dismiss/snooze writes**: `NotificationActionReceiver` launches fire-and-forget `CoroutineScope(IO)` without `goAsync()` — process can die before DataStore writes land (NotificationActionReceiver.kt:33-76).
3. **Non-atomic seen-set updates** → duplicate notifications under concurrent FCM + poll (PokemonAlertsRepository.kt:180-194).
4. **NPE risk**: `PokebattlerAuthRepository.refresh` uses `token()!!` after a header check.
5. **Missing `ACCESS_NETWORK_STATE`** in the manifest — PokeBattler offline-cache interceptor only works because Firebase's merged manifest contributes it.
6. **Plaintext GoDex session cookies** in DataStore — encrypt like the PokeBattler JWT already is (Keystore AES/GCM), with migration.
7. **Lenient endTime parsing** in `TimeUtils` — numeric non-epoch strings read as 1970 epoch-millis (instantly expired), device-TZ assumptions.
8. **Notification id / PendingIntent request-code collisions** from `hashCode()` + fixed offsets.
9. **Duplicate location caches** (AlertNotifier's private cache vs CachedLocationProvider) → unify so notifications and widgets agree on distance.
10. **Dead/dangerous code**: unused `upsertAlert`, `AlertDao.deleteExpired` lexicographic string compare, always-true version checks (minSdk 26).
11. **Exported widget receivers** accept custom actions from any app — restrict where possible.
12. **GoDexWriteWorker permanent failure silently drops the user's toggle** — surface it in the GoDex settings UI.
