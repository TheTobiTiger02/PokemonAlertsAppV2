## Feature 1 — Pick a saved Google account for Pokébox (Pokebattler) and GoDex sign-in

**Context from exploration:** both logins are WebView-based OAuth — the app has no native email/password fields; you type Google credentials on Google's own page inside a WebView, and the app only harvests the resulting Pokebattler JWT / godex.site cookies. A native Google Sign-In token can't be exchanged with third-party websites, so the plan is: pick an account from the device's saved Google accounts via the **system account chooser** (`AccountManager.newChooseAccountIntent` — the sanctioned, permission-free API), then pass the chosen email to Google's OAuth page inside the WebView as the standard `login_hint` parameter. Google then pre-fills/pre-selects that account; you only type the password on Google's page (the app never sees credentials, matching the current design and GoDex screen's "never stores your email or password" promise — the email is kept in memory only).

Changes:
1. **New util `util/GoogleAccountLoginHint.kt`** — pure, JVM-testable: `apply(url, email): String?` returns a rewritten URL only for `accounts.google.com` OAuth sign-in URLs (path contains `/o/oauth2` or `/ServiceLogin`), appending or replacing `login_hint=<urlencoded email>`; returns null when nothing should change (this is also the redirect-loop guard).
2. **`PokebattlerLoginActivity`** — when provider is GOOGLE: a "Choose Google account" button above the WebView (shows the picked email once chosen). Tapping it launches the system chooser via `rememberLauncherForActivityResult`; the result email is stored in session state and the login URL reloads. `shouldOverrideUrlLoading` and `onPageStarted` run every main-frame URL through `GoogleAccountLoginHint` and reload when rewritten (covers both link clicks and the server-side 302 onto accounts.google.com).
3. **`GoDexLoginActivity`** — same treatment: a "Choose Google account" action in the existing top bar next to "Use another account", same hint rewrite in its WebViewClient.
4. **`strings.xml`** — new strings for the button/selected-account label.
5. **Unit test `GoogleAccountLoginHintTest`** — append / replace-different-hint / no-op-when-present / non-Google URL untouched / encoding.

No new permissions, no new dependencies. If no Google accounts exist on the device, the chooser simply offers to add one.

## Feature 2 — Import the base form alongside every mega/primal row

Since Poké Genie merges base + mega and only exports the mega row, the CSV import will synthesize the missing base row (the export side is Poké Genie's, so this happens at import):

1. **New `data/pokegenie/MegaBaseExpander.kt`** — for each row whose form is "Mega"/"Mega X"/"Mega Y"/"Primal" (detected via the existing `PokeGenieMatcher.matchKeysFor` + `isMegaOrPrimalId`):
   - Synthesize a base row: same IVs, moves, gender, lucky, favorite, shadow state; `form = null`; display name with the "Mega X/Y" prefix stripped (same modifier-stripping as `PokebattlerNameNormalizer`).
   - **Level = min(mega level, 50)** per your choice — 52 → 50 exactly as you specified; unboosted megas (Mega Level 1–3) keep their level unchanged. `levelMin`/`levelMax` set to the same value.
   - CP/HP left empty on the synthesized row — the mega's values would be wrong for the base form and can't be derived without base stats (CP is display/tiebreak only; Pokebattler ranking is level-bucketed).
   - Dedupe: skip synthesis when the CSV already contains a real base row of that species (matched by bare-species Pokebattler id + shadow state), and only one synthesized base per species even if you own both Mega X and Mega Y (highest resulting level wins).
2. **`PokeGenieRepository.prepareImport`** runs the expansion right after parsing, so the preview and all counts include the base rows; `PokeGenieImportSummary` gains a `synthesizedBaseCount`. `commitImport` needs no change (it maps whatever rows the candidate holds).
3. **Preview/confirmation UI** (`RaidCountersSettingsContent` + strings): when > 0, show "includes N base forms added for your megas".
4. **Tests**: new `MegaBaseExpanderTest` (52→50, ≤50 unchanged, X+Y → single base, real base row already present → skipped, primal row, missing level); a mega-row fixture in `PokeGenieCsvParserTest`; an end-to-end case in the instrumented `PokeGenieRepositoryTest`.

Effect: the base form gets its own Pokebattler id (e.g. `CHARIZARD` vs `CHARIZARD_MEGA_Y`), so you get counter recommendations for the base form even when only the mega was scanned — and the existing one-active-mega rule in `suggestTeam` already models "can't use both at the same time".
